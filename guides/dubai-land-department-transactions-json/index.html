Dubai Land Department transactions as JSON: registered sold prices, weekly volumes and how to pull them

The Dubai Land Department (DLD) publishes every registered property transaction in Dubai as open data: each sale, off-plan pre-registration, mortgage registration and gift, with the transaction date, the value in AED, the area, project and master project, property type, rooms, parking and size. It is the only source of actual registered prices for Dubai; listing portals show asking prices. This guide explains what the register contains, how much data it produces and how to pull it as JSON.

What a week of DLD data looks like (measured 11 to 18 October 2026)

Transaction group Transactions per week Notes
Sales about 2,600 1,650 off-plan (developer pre-registrations), 950 ready properties
Mortgages about 1,300 registrations and modifications, separated by the procedure field
Gifts about 160 transfers between family members
Land plots about 220 of the sales propertyType: "land"
Total about 4,100 a typical week is 3,000 to 6,000

Roughly 2,500 of the 2,600 weekly sales are residential; the rest are commercial.

Fields in each record

Every record carries the transaction date (ISO), transaction number, procedure (for example Sale, Delayed Sell, Sell - Pre registration, mortgage registration or modification), transaction group, property type and sub-type, usage (residential or commercial), area, project and master project names, rooms, parking, actual area in square metres, value in AED and a precomputed pricePerSqmAed, plus boolean off-plan and freehold flags. Arabic names are available as an optional object. The register contains no owner names or contact details.

Free portals versus the register as data

Dubai Pulse (the government open-data portal) and DXB Interact (DLD's dashboard) let you look up transactions and download extracts by hand. They are the right tools for a one-off question. They are the wrong tools for a daily feed into a database, a valuation model that needs price per square metre by project, or an app that shows registered prices next to listings, because each extract is manual and the files need cleaning. The Daemon Data API reads the same DLD open-data service, pages through the whole date range 500 rows at a time and returns analysis-ready records.

How to pull it

One call returns last week's residential unit sales (about 2,500 rows, about $2.50):

curl -X POST "https://api.apify.com/v2/acts/data_daemon~dubai-property-transactions/run-sync-get-dataset-items?token=YOUR_APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"daysBack": 7, "transactionGroup": "sales", "usage": "residential", "propertyType": "unit", "maxItems": 0}'

For a daily feed, save the input with daysBack: 1 as a task and schedule it; the ready-made example page "Dubai DLD property transactions, last 24 hours, as JSON" returned 1,000 transactions in 6 seconds on 21 October 2026. For a date range use fromDate and toDate (YYYY-MM-DD). To filter by area, read the area and project fields of the output; the service's own area id filter returns no rows at present.

What it costs

$1 per 1,000 transactions, nothing else. A month of all sales (about 11,000 rows) costs about $11; a weekly residential feed about $2.50 a week; a daily feed of everything about $17 a month. Apify's free plan includes $5 of usage every month.

Questions and answers

Is this official Dubai Land Department data?

Yes. The API reads the Dubai Land Department's own open-data transactions service, the same register that paid DLD data products resell. It is published by the department for reuse.

Are these asking prices or sold prices?

Registered transaction values, that is what buyers actually paid or what was registered for a mortgage or gift. Asking prices come from listing portals and are not in the register.

How do I tell an off-plan pre-registration from a completed sale?

Use the procedure field: Sell - Pre registration is a developer pre-registration, Sale and Delayed Sell are completed sales. The offPlan input filter and the boolean flag in each record do the same split.

Does the register include owner names?

No. The open-data service carries no personal data, and the API adds none.

How far back can I go?

Any date range the DLD service holds; the input accepts fromDate and toDate, or daysBack up to 365.
