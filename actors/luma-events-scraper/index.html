Luma (lu.ma) events as JSON API

Luma Events Scraper is a pay-per-record Apify Actor by Daemon Data that returns lu.ma events by city, category, keyword or calendar: dates, venue, tickets, hosts as JSON, CSV or Excel. It costs $0.0015 per event with the default options ($1.50 per 1,000); no login to the source site, no proxy, no browser, and the same input runs from the Apify console, one REST call, Python, Node.js, n8n or an AI assistant through MCP.

Input and how to call it

A verified example input (it returned data on 2026-10-30):

{
  "cities": [
    "London"
  ],
  "categories": [
    "ai"
  ],
  "daysAhead": 30,
  "includeDetails": true,
  "maxEvents": 50
}

One HTTP call starts a run, waits for it and returns the records (token from console.apify.com):

curl -X POST "https://api.apify.com/v2/acts/data_daemon~luma-events-scraper/run-sync-get-dataset-items?token=YOUR_APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"cities": ["London"], "categories": ["ai"], "daysAhead": 30, "includeDetails": true, "maxEvents": 50}'

Python: ApifyClient(token).actor("data_daemon/luma-events-scraper").call(run_input=...), full file python/luma-events-scraper.py. Node.js: node/luma-events-scraper.mjs. n8n: importable workflow. AI assistant (MCP): add the remote server https://mcp.apify.com/?tools=data_daemon/luma-events-scraper with header Authorization: Bearer YOUR_APIFY_TOKEN in Claude, ChatGPT, Cursor or VS Code and ask for the data in plain words.

All input fields

FieldTypeMeaning
citiesarrayLuma discover cities, e.g. San Francisco, New York, London, Berlin, Bengaluru, Tokyo, Singapore (87 cities; a lu.ma/<city> URL or a discplace-... id works too). One upcoming-events feed per city, newest start date last. An event found in two feeds is saved and charged once. Leave one city for a quick first run; set the list empty to search worldwide with a keyword.
categoriesarrayOptional. Luma categories: ai, tech, arts, climate, crypto, fitness, wellness, running, books, games, family, fooddrink. Each category is scraped around each city above (Luma lists category events by location). Several categories = any of them.
querystringOptional keyword searched by Luma in event names and descriptions, e.g. hackathon, founders, yoga, web3. Applied inside each city, category and calendar feed (Luma returns the 50 best matches per feed). With cities set to an empty list and no other source, it searches worldwide.
startUrlsarrayOptional. Any public lu.ma / luma.com link: an organiser calendar (https://lu.ma/planetscale), a single event (https://lu.ma/qjw9i5a9), a city (https://lu.ma/sf) or a category (https://lu.ma/ai); cal-..., evt-..., discplace-... ids too. Calendars return their upcoming events. When only URLs are given, the default city is not scraped.
daysAheadintegerOnly events starting within the next N days (1-365), e.g. 7 for this week's events. Leave empty for all upcoming events (feeds are ordered by start date, so maxEvents takes the soonest ones).
startDateFromstringOptional earliest start date, YYYY-MM-DD or ISO date-time (UTC), e.g. 2026-11-01. Applied by Luma's own date cursor, so later pages are not fetched for nothing.
startDateTostringOptional latest start date, YYYY-MM-DD (inclusive) or ISO date-time. Each feed stops at the first event after this date.
priceTypestringany (default), free (ticket price 0 / no ticket) or paid (at least one paid ticket type). Checked on every event before it is saved or charged.
eventFormatstringany (default), in-person (events with a physical venue) or online (no venue or a meeting link as the venue, incl. events whose location is not announced).
includeDetailsbooleanOn (default): one extra request per new event adds the full description (plain text and HTML), every public ticket type with its price, the event's Luma categories and the sold-out flag. The price per event is the same either way. Off: feed fields only (name, dates, venue, GPS, price range, hosts, calendar, guest count), roughly twice as fast.
maxEventsintegerStop after this many saved events (default 25). Cost: $0.0015 per event with details, so 25 events = $0.04. A city has 50-150 upcoming events; raise this for full exports.
maxEventsPerSourceintegerOptional cap per feed so one busy city does not use up maxEvents (0 = no cap).
onlyNewSinceLastRunbooleanOn: deliver only events that an earlier run with the same stateName has not already delivered, and skip the rest without charging. Off (default): return every matching event.
stateNamestringOptional name for this search's memory when onlyNewSinceLastRun is on, e.g. sf-ai-daily. Leave empty to derive it from the cities, categories, keyword and URLs. Use a new key to start over.
skipEventIdsarrayEvent ids you already have (the id field from earlier runs, e.g. evt-Dgnnl0IoUmK5Se1; lu.ma/<slug> URLs are accepted too). Skipped before any detail fetch and never charged. Large lists are fine.

What it is not for

Eventbrite, Meetup (not covered); attendee or guest lists (never collected). The data belongs to its publisher; the Actor reads public pages and endpoints and leaves out personal contact details.

Questions buyers ask

How much does it cost to scrape Luma?

$0.0015 per event with its full details plus $0.001 per run, so 100 events cost about $0.15 and a daily feed of 20 new events about $1 a month.

Is there an official Luma API?

Luma has a paid API for calendar owners (their own events). This Actor reads the public JSON that the lu.ma website itself loads for discover, category, calendar and event pages, and exposes it as a REST API with schedules, webhooks and only-new runs. No login or API key is needed.

Does it collect attendees or guest lists?

No. The Actor never requests or outputs guest lists, guest names, e-mails or phone numbers, including the "N going" avatars shown on event pages. It outputs the hosts' and organiser calendar's public profile information exactly as the event page shows it (name, bio, profile URL, website and social handles).

Why is the address missing on some events?

Hosts can show the exact address only to registered guests. Luma then shows the city and neighbourhood, and so does the Actor: address and venue are null, addressHidden is true, and the coordinates are rounded to about 1 km. City, region and country are still filled in.

Why does an online-only run of a city return nothing?

Luma's city and category pages list events with a physical location near that city. Online events are found through organiser calendars (startUrls) and keyword searches with cities: [], and are marked format: "online".

Which cities and categories exist?

The 87 cities on lu.ma/discover (any lu.ma/<city> page; the Actor also resolves new cities live) and the 12 categories ai, tech, arts, climate, crypto, fitness, wellness, running, books, games, family, fooddrink. A city or category Luma does not know ends the run with Saved 0 events and the known examples in the status message.

Can I scrape past events?

Not in this version: Luma's public feeds list upcoming events. Open an issue if you need an organiser's past events.

Does it work for luma.com links?

Yes. lu.ma and luma.com are the same site; paste either form in startUrls.
