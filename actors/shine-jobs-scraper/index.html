Shine.com job listings as JSON API

Shine Jobs Scraper is a pay-per-record Apify Actor by Daemon Data that returns Shine.com India jobs by keyword and city with full descriptions, salary range, experience, skills and industry as JSON, CSV or Excel. It costs $0.0008 per job with the default options ($0.80 per 1,000); no login to the source site, no proxy, no browser, and the same input runs from the Apify console, one REST call, Python, Node.js, n8n or an AI assistant through MCP.

Input and how to call it

A verified example input (it returned data on 2026-10-28):

{
  "searchTerms": [
    "data analyst"
  ],
  "cities": [
    "Pune"
  ],
  "postedWithinDays": 7,
  "includeDescription": true,
  "maxJobsPerSearch": 50
}

One HTTP call starts a run, waits for it and returns the records (token from console.apify.com):

curl -X POST "https://api.apify.com/v2/acts/data_daemon~shine-jobs-scraper/run-sync-get-dataset-items?token=YOUR_APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"searchTerms": ["data analyst"], "cities": ["Pune"], "postedWithinDays": 7, "includeDescription": true, "maxJobsPerSearch": 50}'

Python: ApifyClient(token).actor("data_daemon/shine-jobs-scraper").call(run_input=...), full file python/shine-jobs-scraper.py. Node.js: node/shine-jobs-scraper.mjs. n8n: importable workflow. AI assistant (MCP): add the remote server https://mcp.apify.com/?tools=data_daemon/shine-jobs-scraper with header Authorization: Bearer YOUR_APIFY_TOKEN in Claude, ChatGPT, Cursor or VS Code and ask for the data in plain words.

All input fields

FieldTypeMeaning
searchTermsarrayJob titles or skills, one Shine search each, e.g. python, data analyst, accountant, sales executive, java developer, nurse. Leave empty to list all jobs (in the given cities, or in India). A job found by two searches is saved and charged once.
citiesarrayCities as Shine names them, e.g. Bangalore, Mumbai, Delhi, Gurgaon, Noida, Hyderabad, Pune, Chennai, Kolkata, Ahmedabad, Navi Mumbai. Each keyword runs once per city. Shine also suggests jobs in nearby cities; the Actor keeps only jobs located in the city you asked for.
experienceYearsintegerOnly jobs whose experience range covers this many years, e.g. 2 keeps "1 to 3 Yrs" and "0 to 4 Yrs" but not "5 to 8 Yrs".
postedWithinDaysintegerOnly jobs posted in the last N days (e.g. 1 for a daily feed). Results are read newest first, so the search stops at the first page of older jobs. 0 or empty = any date.
includeDescriptionbooleanOpen each job page for the full description (text + HTML), numeric salary range, industry, function, employment type and expiry date. Turn off for a fast list of titles, companies, cities, experience, salary text and skills. Price is the same either way.
maxJobsPerSearchintegerCap for each keyword (and city). Newest jobs come first. 0 = no cap (a popular keyword can have tens of thousands of jobs; set a maximum cost per run).
maxJobsintegerStop after this many saved jobs. 0 or empty = no total cap (the run's maximum cost still applies).
onlyNewSinceLastRunbooleanFor schedules: remember delivered job ids (in a named key-value store in your account) and save only jobs that earlier runs with the same settings did not deliver. Skipped jobs are not charged.
stateNamestringName of the only-new memory. Empty = derived from the keywords, cities and experience. Give two schedules the same name to share one memory.
skipJobIdsarrayShine job ids you already have (the id field). They are neither fetched, saved nor charged.

Questions buyers ask

Is there an official Shine API?

Not a public one. This Actor reads Shine's public search and job pages, which robots.txt allows, and exposes them as a REST API with schedules, webhooks and only-new runs.

Why do some jobs have no salary numbers?

The employer chose "Not Disclosed". salaryText then says so.

Do I need a proxy?

No. If Shine starts refusing direct requests, the Actor switches to Apify's anti-bot proxy by itself.
